# 몸 나눠쓰기 · Body Share

모바일 세로 화면을 우선으로 만들고, PC에서도 동일한 규칙을 테스트하는 작은 퍼즐입니다.

> 내 머리가 한 칸 늘어나면, 상대 꼬리가 한 칸 줄어듭니다. 두 얼굴을 각자의 집으로 보내세요.

## v0.2.0
입문·기초·응용·도전 각 3개, 총 12개 스테이지. 자유로운 되돌리기, 양쪽 모두 막혔을 때 안내, 스테이지별 자동 저장, 단계별 힌트와 별도 시범을 제공합니다. 상업 시스템·새 장치·목숨·시간 제한은 없습니다.

난이도는 제작자가 붙인 임시 분류입니다. 해답 존재/최단 경로/대표 막힘은 자동 검증했지만, 실제 이용자 난이도나 실기기 품질은 별도 플레이 테스트가 필요합니다.

## PC 개발·테스트
Node.js 22 이상에서 실행합니다. 실행 의존성이 없으므로 `npm install` 없이도 됩니다.

```sh
npm start
# http://127.0.0.1:5173
```

`1` / `2`: 친구 선택. 방향키 또는 WASD: 한 칸 이동. `Z`: 되돌리기. `R`: 초기화 확인. `H`: 다음 힌트.
마우스로 얼굴을 드래그하거나 친구를 선택한 뒤 인접한 칸을 클릭할 수도 있습니다.
PC 오른쪽 **모바일 폭 보기**는 390px 배치를 보여줍니다. **PC 테스트 정보**에서 가능한 이동 수·기준 최소 걸음·무효 입력·막힘·되돌리기·초기화 횟수를 확인하고 JSON 기록을 내려받을 수 있습니다. 막힘 시범은 실제 진행을 변경하지 않습니다.

같은 신뢰할 수 있는 Wi-Fi의 휴대전화로 PC 개발 서버에 접속하려면 `npm run dev:lan` 후 PC의 로컬 IP와 5173 포트를 사용합니다. 필요하면 로컬 방화벽을 해당 사설 네트워크에서만 허용하세요. 공유기 포트 포워딩은 필요하지 않습니다.

## GitHub Pages
이 프로젝트에는 별도 서버/데이터베이스/외부 CDN이 필요하지 않습니다. GitHub Pages가 현재 범위에 가장 간단합니다.

최초 한 번 저장소 **Settings → Pages → Build and deployment → Source → GitHub Actions**를 선택합니다.
그다음 **Actions → Verify and publish → Run workflow**를 실행합니다. 이후 main 반영 시 자동 검증·빌드·배포합니다.

예상 주소: https://herothgf-cell.github.io/project-d/
이 주소는 최초 설정과 배포 성공 전에는 열리지 않습니다. Actions의 `Deploy` 단계와 실제 HTTP 응답으로 공개 여부를 확인하세요. `verify` 성공만으로 배포가 완료된 것은 아닙니다.

워크플로는 Pages가 비활성화된 경우 경고와 설정 방법을 표시하고 배포를 건너뜁니다. 기본 GITHUB_TOKEN으로 관리자 최초 설정을 우회하지 않습니다.

대안으로 Source를 `Deploy from a branch`, branch `main`, folder `/(root)`로 지정해도 실행할 수 있습니다. 단, 권장 방식은 테스트 통과 뒤 빌드 결과만 공개하는 GitHub Actions입니다. 현재 범위에서는 Vercel 등 새 계정을 추가할 필요가 없습니다.

## 자동 검사와 빌드
```sh
npm test
npm run check:levels
npm run build
```
`dist/index.html`은 CSS·코드·스테이지를 모두 포함한 독립 HTML입니다. 내려받아 브라우저로 열어 PC에서 테스트할 수도 있습니다. 브라우저의 파일 저장 제한이 있으면 저장 경고가 표시되지만 게임은 실행됩니다.

브라우저 자동 검사는 Python 3.10 이상과 Playwright가 추가로 필요합니다.
```sh
python -m pip install playwright==1.57.0
python -m playwright install chromium
npm run test:ui
```
실제 HTTP 로컬 서버에서 키보드·마우스·터치 에뮬레이션·재접속·저장을 검사합니다. `BROWSER_PATH`로 별도 Chromium 경로를 지정할 수 있습니다.

네트워크 탐색이 금지된 샌드박스에서는 `UI_OFFLINE=1 python tests/ui_test.py`를 사용합니다. 이 모드는 로컬 HTML을 직접 로드하고 저장 어댑터를 사용하므로 **실제 HTTP/브라우저 localStorage 검증과 구분해야 합니다.** 관리자 보안 정책을 변경하지 않습니다.

## 저장과 실패
저장은 해당 브라우저·주소의 localStorage에만 있습니다. PC와 모바일/다른 브라우저로 동기화되지 않으며 사이트 데이터 삭제 시 사라집니다. 유효한 행동 목록을 재실행해 복구하므로 저장을 임의로 바꿔 불가능한 배치를 넣을 수 없습니다. 배치가 변경된 스테이지만 옛 진행을 무효화합니다. v0.1 실험판의 진행은 가져오지 않습니다.

이번에 사라질 꼬리도 이동 전에는 점유된 칸입니다. 성공이 막힘보다 먼저 판정됩니다. 무효 입력은 걸음이나 실패로 세지 않습니다. 양쪽 합법 이동이 모두 없는 경우만 막힘으로 알립니다. 움직일 수 있어도 해답이 사라진 상태까지 실시간으로 판정하지는 않습니다.

## 구조
- `src/core.js`: 상태와 규칙, 가능한 이동, 제한 있는 최단 풀이기.
- `src/session.js`: 되돌리기·기록·검증된 저장/복구.
- `src/levels.js`: 12개 배치, 힌트, 해답과 대표 막힘.
- `src/app.js`, `src/style.css`, `index.html`: 동일 엔진을 사용하는 모바일/PC 화면.
- `scripts/`: 개발 서버, 독립 HTML 빌드, 레벨 검증.
- `tests/`: 단위·레벨·브라우저 검사. `test-results/`에 결과 생성.
- `docs/DESIGN.md`, `docs/LEVELS.md`, `docs/TESTING.md`: 규칙/제작/검증 기록.

모바일 에뮬레이션은 실제 iOS Safari/Android Chrome 검사와 같지 않습니다. 출시 플랫폼 포장, 오프라인 서비스 워커, 계정/온라인 기능은 이번 범위에 포함하지 않았습니다.
